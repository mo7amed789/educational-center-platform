# خطة تحويل منصة السنتر إلى نظام مؤسسي

## نقطة البداية

المشروع الحالي صفحة HTML محلية تعتمد على `localStorage`. سيتم الحفاظ على
`center-admin-v2.html` كواجهة legacy ومصدر بيانات قابل للترحيل، مع بناء طبقة
خلفية تدريجية دون اعتبار localStorage مصادراً موثوقاً للمصادقة أو الصلاحيات.

## القرارات المعمارية

- TypeScript + Fastify لواجهة API صغيرة وواضحة.
- Prisma كـ ORM مع SQLite في التطوير المحلي، مع قابلية التحويل إلى PostgreSQL
  عبر `DATABASE_URL` في بيئة الإنتاج.
- جلسات opaque داخل قاعدة البيانات عبر Cookie `httpOnly`، دون وضع tokens في
  localStorage.
- RBAC بصلاحيات دقيقة، مع `centerId` على كل سجل مؤسسي وفلترة إجبارية في
  طبقة الوصول.
- Zod للتحقق من مدخلات API وHelmet وRate Limit وCSRF عبر SameSite cookies.
- مسار migration قابل لإعادة التشغيل لنسخ JSON القديمة.

## ترتيب التنفيذ

1. Foundation: قاعدة البيانات، الجلسات، RBAC، عزل المراكز، health check.
2. Legacy migration: التحقق والاستيراد الآمن للمدرسين والمجموعات والطلاب
   والحضور والمدفوعات.
3. Core management: الطلاب والمدرسون والمجموعات والفروع والجداول.
4. Operations: الحضور، الرسوم، المدفوعات، الإيصالات والتقارير.
5. Portals: مدير المركز، المحاسب، المدرس، الطالب، ولي الأمر.
6. Academic and communication: التقييمات والواجبات والإشعارات والتكاملات.
7. Hardening and release: الاختبارات، التدقيق، النسخ الاحتياطي، CI والتوثيق.

## حدود هذه الشريحة

المكتمل هنا هو الأساس التنفيذي الآمن ومسار migration. لا تُعد المنصة
production-ready قبل اكتمال الوحدات اللاحقة، إعداد PostgreSQL، HTTPS، إدارة
الأسرار، ومراجعة أمنية مستقلة.
